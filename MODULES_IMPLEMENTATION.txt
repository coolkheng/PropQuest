MODULE 2: DATA STORAGE AND MANAGEMENT MODULE
================================================================================

Requirement ID: FR_04, FR_05, FR_06
Status: COMPLETED

Implementation Details:
------------------------
1. MongoDB Database Setup
   - Database: propertyguruPJ
   - Collection: properties19nov
   - Total Documents: ~5,000 property listings
   - Connection: MongoDB Atlas cloud database
   - File: backend/lib/mongodb.ts, backend/api/index.js

2. Data Schema Structure
   Property documents contain the following fields:
   - _id: Unique identifier
   - title: Property title/name
   - price: Property price (mixed type: string/number)
   - address: Full address with location details
   - house_type: Property type (Condominium, Apartment, Terrace, etc.)
   - size_sqft: Property size (mixed type: string/number)
   - beds: Number of bedrooms (mixed type: string/number)
   - baths: Number of bathrooms (mixed type: string/number)
   - facilities: Array of amenities/facilities
   - images: Array of image URLs
   - updated_at: Timestamp for listing freshness (FR_06)

3. Data Type Handling & Cleansing
   - Implemented data conversion pipeline to handle mixed string/number types
   - Price conversion: Strip "RM", commas, spaces before converting to numeric
   - Size conversion: Strip "sq.ft.", commas, spaces before converting to numeric
   - Beds/Baths conversion: String to numeric with null safety
   - MongoDB aggregation $convert with onError and onNull handlers

4. Bulk Operations Support (FR_05)
   - MongoDB upsert operations implemented for efficient updates
   - Prevents duplicate records through unique identifiers
   - Timestamps maintained for tracking listing updates

Technical Achievements:
- Robust data type normalization handling inconsistent data formats
- Efficient indexing for fast query performance
- Null-safe data access throughout application

MODULE 3: SEARCH AND FILTERING MODULE
================================================================================

Requirement ID: FR_07, FR_08, FR_09, FR_10
Status: COMPLETED

Functional Requirements Achieved:
----------------------------------
FR_07: The system should allow listings to be queried by filters such as location, 
       price, type, and size.
       
FR_08: The system should return matching results sorted by relevance or latest 
       update date.
       
FR_09: The system should support additional bedroom and bathroom count filters 
       for refined search capabilities.
       
FR_10: The system should implement server-side pagination with configurable page 
       size and provide metadata (total pages, total properties, current page).

Implementation Details:
------------------------
1. Query Filtering System (FR_07)
   File: backend/api/index.js - GET /api/properties

   Available Filters:
   a) Location Filter
      - Parameter: location (query string)
      - Implementation: Case-insensitive regex search on address field
      - Example: ?location=kuala%20lumpur

   b) Price Range Filter
      - Parameters: minPrice, maxPrice
      - Implementation: Numeric comparison on converted price values
      - Handles both string and numeric price formats
      - Example: ?minPrice=500000&maxPrice=1000000

   c) Property Type Filter
      - Parameter: type
      - Implementation: Case-insensitive regex match on house_type
      - Supports: Condominium, Apartment, Terrace, Bungalow, etc.
      - Example: ?type=condominium

   d) Size Filter
      - Parameters: minSize, maxSize (in sqft)
      - Implementation: Numeric comparison on converted sqft values
      - Example: ?minSize=700&maxSize=1500

   e) Bedroom Filter
      - Parameter: beds
      - Implementation: Exact or minimum match on bedroom count
      - Example: ?beds=3

   f) Bathroom Filter
      - Parameter: baths
      - Implementation: Exact or minimum match on bathroom count
      - Example: ?baths=2

2. Results Sorting (FR_08)
   - Default Sort: Latest update date (updated_at descending)
   - Relevance Sort: Available through ranking score (Module 4)
   - Implementation: MongoDB $sort aggregation stage

3. Pagination System
   - Page-based pagination (60 items per page)
   - Parameters: page (default: 1)
   - Returns: properties array, currentPage, totalPages, totalProperties
   - Efficient server-side pagination using $skip and $limit

4. Frontend Implementation
   Files:
   - propquest/app/listing/page.tsx - List view with filters
   - propquest/app/page.tsx - Map view with filters
   - propquest/components/listing-controls.tsx - Filter controls
   - propquest/components/map-controls.tsx - Map filter controls

   Features:
   - Real-time filtering without page reload
   - Filter state management using React hooks
   - URL parameter synchronization for shareable filtered URLs
   - "Load More" functionality for seamless browsing

Technical Achievements:
- Combined multiple filters in single MongoDB query
- Optimized query performance with proper indexing
- Responsive filter UI with Tailwind CSS
- Case-insensitive search for better UX

MODULE 4: RANKING AND RECOMMENDATION MODULE
================================================================================

Requirement ID: FR_12, FR_14, FR_15, FR_16
Status: COMPLETED

Functional Requirements Achieved:
----------------------------------
FR_12: The system should rank listings by relevance to user-defined preferences 
       using a multi-category weighted scoring algorithm (100-point scale across 
       7 categories: location, price, type, size, rooms, bathrooms, keywords).

FR_14: The system should implement precision location matching using word-boundary 
       regex patterns to prevent false positive matches (e.g., "ss2" matches only 
       "ss2", not "ss21" or "ss24").

FR_15: The system should provide a user-friendly multi-step wizard interface for 
       setting and managing user preferences with validation at each step.

FR_16: The system should fall back to default ranking by recency when no preference 
       data is provided, ensuring functionality for anonymous users.

Implementation Details:
------------------------
1. User Preferences System (FR_09)
   File: backend/api/index.js - /api/users/me/preferences

   Stored Preferences:
   - preferred_locations: Array of location keywords
   - budget_range: { min, max } price range
   - preferred_types: Array of property types
   - keywords: Array of facility/amenity keywords
   - min_size_sqft: Minimum property size
   - ideal_size_sqft: Ideal property size
   - rooms: Preferred number of bedrooms
   - toilets: Preferred number of bathrooms
   - size_tolerance_pct: Acceptable size deviation percentage
   - radius_km: Search radius (optional)
   - updated_at: Last update timestamp

   Frontend: propquest/app/preferences/page.tsx
   - 6-step wizard interface for setting preferences
   - Steps: Locations → Budget → Property Types → Facilities → Size → Review
   - Progress indicator with step validation
   - Real-time preference summary display

2. Personalized Ranking Algorithm (FR_10)
   File: backend/api/index.js - GET /api/properties/personalized

   Total Score: 100 Points distributed across 7 categories:

   a) Location Matching (40 points)
      - Exact location match in address
      - Uses word boundary regex: (^|\s|,)location(\s|,|$)
      - Prevents false matches (e.g., "ss2" won't match "ss21" or "ss24")
      - Case-insensitive matching

   b) Price Scoring (30 points)
      - Within budget range: Full 30 points
      - Outside range: Continuous decay based on percentage difference
      - Formula: 30 × (1 - (|price - budget| / budget))
      - Smooth decay for prices near budget boundaries

   c) Property Type Similarity (15 points)
      - Exact match: 15 points
      - Similar types with similarity matrix:
        * Condominium ↔ Service Residence: 12 points
        * Condominium ↔ Apartment: 10 points
        * Terrace ↔ Townhouse: 12 points
        * Semi-Detached ↔ Bungalow: 8 points
      - Implemented using MongoDB $switch with regex matching

   d) Size Matching (10 points)
      - Within tolerance range: Full 10 points
      - Outside range: Smooth decay based on percentage difference
      - Respects user-defined size_tolerance_pct
      - Formula: 10 × max(0, 1 - percentDiff)

   e) Bedroom Matching (3 points)
      - Distance-based scoring: 3 - |actual - preferred|
      - More forgiving than binary match
      - Minimum score: 0

   f) Bathroom Matching (2 points)
      - Distance-based scoring: 2 - |actual - preferred|
      - Minimum score: 0

   g) Keyword/Facilities Matching (5 points)
      - Proportional scoring: (matched keywords / total keywords) × 5
      - Searches in: title, address, facilities array
      - Case-insensitive matching
      - Formula: (hits / total) × 5

3. Advanced Aggregation Pipeline
   - Multi-stage MongoDB aggregation
   - Type conversion for mixed data types
   - Nested $let variables for complex calculations
   - $cond, $switch for conditional scoring
   - $filter for array operations
   - $regexMatch for pattern matching
   - Results sorted by score descending
   - Top 100 properties returned

4. Default Ranking Fallback (FR_11)
   - When no preferences set: Standard listing by update date
   - Graceful degradation ensures functionality without user account
   - Anonymous users see chronological listings

5. "For You" Page Implementation
   File: propquest/app/foryou/page.tsx
   
   Features:
   - Authentication guard (redirects to login if not signed in)
   - Empty state prompts users to set preferences
   - Displays personalized properties ranked by score
   - Same UI as listing page for consistency
   - Navigation buttons: Map | For You | List
   - Pagination support (60 items per page)

Technical Achievements:
- Sophisticated 7-category scoring algorithm
- MongoDB aggregation expertise with nested calculations
- Variable scoping management in complex pipelines
- Continuous decay functions for smooth scoring
- Property type similarity matrix for intelligent recommendations
- Real-time score computation on-demand
- Optimized to return results in < 2 seconds

------------------------

   - Framework: Express.js on Node.js

   - CORS Configuration: Enabled for localhost:3000 (Next.js frontend)
   - Credentials Support: withCredentials for cookie-based auth
   - File: backend/api/index.js

2. Core API Endpoints (FR_13)

   a) Property Endpoints:
      GET /api/properties
      - Query all properties with filtering
      - Parameters: location, type, minPrice, maxPrice, minSize, maxSize, beds, baths, page
      - Returns: Paginated property list with metadata
      - Status: IMPLEMENTED

      GET /api/properties/personalized
      - Get ranked properties based on user preferences
      - Requires: Authentication (JWT token)
      - Returns: Scored and sorted properties
      - Status: IMPLEMENTED

      GET /api/properties/:id
      - Get detailed view of single property
      - Returns: Full property object with all fields
      - Status: IMPLEMENTED

   b) User Authentication Endpoints:
      POST /api/register
      - Create new user account
      - Body: { name, email, password }
      - Returns: Success message
      - Password hashing: bcrypt
      - Status: IMPLEMENTED

      POST /api/login
      - Authenticate user credentials
      - Body: { email, password }
      - Returns: JWT token in httpOnly cookie
      - Token expiry: 7 days
      - Status: IMPLEMENTED

      POST /api/logout
      - Clear authentication token
      - Clears httpOnly cookie
      - Status: IMPLEMENTED

      GET /api/users/me
      - Get current user profile
      - Requires: Authentication
      - Returns: User object without password
      - Status: IMPLEMENTED

   c) User Preferences Endpoints:
      GET /api/users/me/preferences
      - Retrieve user's saved preferences
      - Requires: Authentication
      - Returns: Preferences object
      - Status: IMPLEMENTED

      POST /api/users/me/preferences
      - Save/update user preferences
      - Requires: Authentication
      - Body: { preferences: {...} }
      - Returns: Updated preferences with timestamp
      - Status: IMPLEMENTED

3. Frontend Integration (FR_14)
   - All API calls use Axios with withCredentials: true
   - Base URL: http://localhost:5001
   - Automatic cookie handling for authentication
   - Error handling with user-friendly messages
   - Loading states for better UX

4. API Response Format
   Success Response:
   {
     "properties": [...],
     "currentPage": 1,
     "totalPages": 10,
     "totalProperties": 600
   }

   Error Response:
   {
     "error": "Error message"
   }

5. Authentication Middleware
   - JWT verification on protected routes
   - Token extracted from httpOnly cookie
   - User ID attached to request object
   - 401 Unauthorized for invalid/missing tokens

   - User document structure:
     * name: User's full name
     * email: Unique email address (used for login)
     * password: Bcrypt hashed password
     * preferences: Embedded preferences object
     * created_at: Account creation timestamp

   - Form validation (name, email, password)
   - Client-side password confirmation check
   - Loading state during registration
   - Error message display
   - Auto-redirect to login after successful registration
   - Link to login page for existing users

2. User Login System
   Backend: POST /api/login
   - Email and password validation
   - Bcrypt password comparison
   - JWT token generation with user ID payload
   - Token stored in httpOnly cookie for security
   - Token expiry: 7 days
   - Cookie settings: httpOnly, sameSite: 'strict'

   Frontend: propquest/app/login/page.tsx
   - Email and password form
   - Loading state during authentication
   - Error message display for invalid credentials
   - Remember session via JWT cookie
   - Auto-redirect to home page after successful login
   - Link to registration page for new users

3. Session Management
   Custom Hook: propquest/lib/useSession.tsx
   - Checks authentication status on page load
   - Fetches current user data from /api/users/me
   - Provides: { user, loading } state
   - Used across all protected pages
   - Automatic re-validation on navigation

4. Protected Routes
   Implementation:
   - Authentication guard on /foryou page
   - Automatic redirect to /login for unauthenticated users
   - Preferences page requires authentication
   - API endpoints validate JWT token

5. Logout System
   Backend: POST /api/logout
   - Clears authentication cookie
   - Simple and secure logout

   Frontend:
   - TopBar component includes logout button
   - Clears client-side session state
   - Redirects to home page

6. Security Features
   - Passwords never stored in plain text
   - JWT tokens in httpOnly cookies (XSS protection)
   - sameSite: 'strict' cookie setting (CSRF protection)
   - Password hashing with bcrypt
   - Token expiration for session management
   - CORS restricted to frontend domain

7. User Experience Features
   - Persistent login sessions (7 days)
   - Seamless authentication checks
   - Loading states prevent UI flicker
   - Clear error messages for failed attempts
   - Easy navigation between login and register
   - User name displayed in TopBar when logged in

Technical Achievements:
